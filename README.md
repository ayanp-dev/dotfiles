# Portable USB NixOS Dotfiles

A fully declarative, portable NixOS environment designed to boot from a USB drive and work on any x86_64 machine. The entire system - from bootloader to shell aliases - is defined in Nix, making it trivially reproducible and version-controlled.

Adapted from [kunchenguid/dotfiles](https://github.com/kunchenguid/dotfiles).

## Architecture

The system is managed by two complementary layers, both orchestrated through a single [Nix Flake](flake.nix):

| Layer | File | Scope |
|---|---|---|
| **NixOS** | [`configuration.nix`](configuration.nix) | System-level: bootloader, networking, desktop environment, kernel modules, power management |
| **Home Manager** | [`home.nix`](home.nix) | User-level: shell, editor, terminal, packages, dotfile symlinks, AI agent config |

[`hardware-configuration.nix`](hardware-configuration.nix) is auto-generated by `nixos-generate-config` and carries the disk UUIDs and kernel module list for the USB drive. Both Intel and AMD microcode updates are enabled so the stick boots correctly on either vendor's hardware.

### Flake Inputs

The flake pins four external inputs to the NixOS 26.05 release channel:

- **nixpkgs** - the NixOS package set
- **home-manager** - declarative user environment management
- **herdr** - terminal multiplexer, installed from its own flake
- **claude-code** - Claude Code CLI, via [ryoppippi/nix-claude-code](https://github.com/ryoppippi/nix-claude-code)
- **llm-agents** - Antigravity CLI, via [numtide/llm-agents.nix](https://github.com/numtide/llm-agents.nix)

## Core Tools

### Zsh

The default shell, configured declaratively through Home Manager's `programs.zsh` module:

- **Autosuggestions** - fish-style history suggestions (`Ctrl+F` to accept)
- **Syntax highlighting** - real-time command validation
- **Workflow aliases** - `add`, `push`, `pull`, `m` (switch to main), `cc` (Claude Code), `co` (Codex)

### Starship Prompt

A minimal, fast prompt showing only the directory, git branch/status, command duration, and a purple `>` character.

### Neovim

A Lua-based configuration managed by [Lazy.nvim](https://github.com/folke/lazy.nvim), with plugins organized under `config/nvim/lua/plugins/`:

| Plugin | Purpose | Leader Key |
|---|---|---|
| **oil.nvim** | File browser (editable buffer) | `<Space>e` |
| **snacks.nvim** | Fuzzy finder, notifications, input | `<Space>f` / `<Space>s` / `<Space>b` |
| **which-key.nvim** | Keybinding discovery popup | - |
| **neogit** + **diffview.nvim** | Full Git UI inside Neovim | `<Space>g` |
| **gitsigns.nvim** | Inline git blame and diff signs | - |

Key settings: Space as leader, 2-space indentation, relative line numbers, system clipboard integration (`unnamedplus`), persistent undo, and a generous `scrolloff` of 16 lines.

### WezTerm

GPU-accelerated terminal emulator with:

- **Rose Pine Moon** color scheme
- **Hack Nerd Font** at 13pt
- 80% window opacity, no title bar decorations
- Tab bar hidden when only one tab is open

### Herdr

Terminal multiplexer with tmux-compatible keybindings (`Ctrl+B` prefix):

| Binding | Action |
|---|---|
| `prefix + h/j/k/l` | Navigate panes (vim-style) |
| `prefix + "` | Split horizontal |
| `prefix + %` | Split vertical |
| `prefix + c` | New tab |
| `prefix + &` | Close tab |
| `prefix + w` | Workspace picker |
| `prefix + g` | Goto |
| `prefix + y` | Copy mode |

### Antigravity CLI

Google's agentic AI coding assistant, with a custom [statusline script](config/antigravity/statusline.sh) that displays the active model name and context window usage percentage.

### Claude Code

Anthropic's CLI coding agent, installed via Nix flake with its settings symlinked from the dotfiles repo.

## The `mkOutOfStoreSymlink` Architecture

A standard Home Manager `home.file.*.source` copies files **into** the Nix store, making them read-only. Any edit requires a full rebuild cycle. This is unacceptable for configurations you want to iterate on quickly (editor settings, terminal themes, keybindings).

The solution is `config.lib.file.mkOutOfStoreSymlink`, which creates symlinks that point **directly at the repository working tree** instead of the Nix store:

```
~/.config/nvim  -->  ~/Github/ayanp-dev/dotfiles/config/nvim
~/.config/wezterm  -->  ~/Github/ayanp-dev/dotfiles/config/wezterm
~/.config/herdr  -->  ~/Github/ayanp-dev/dotfiles/config/herdr
~/.claude/settings.json  -->  ~/Github/ayanp-dev/dotfiles/config/claude/settings.json
```

This means:

1. **Live editing** - changes to files under `config/` take effect immediately, no rebuild needed
2. **Single source of truth** - the repo is the live config; there is nothing to sync
3. **Version control for free** - every config change is a `git diff` away

The tradeoff is that the symlink targets are not managed by the Nix store, so they depend on the repository being cloned to the expected path (`~/Github/ayanp-dev/dotfiles`). This path is defined once in the `let` block at the top of [`home.nix`](home.nix).

### AI Agent Instructions

A single [`AGENTS.md`](config/AGENTS.md) file is symlinked into every AI coding agent's expected location:

- `~/.claude/CLAUDE.md` (Claude Code)
- `~/.codex/AGENTS.md` (OpenAI Codex)
- `~/.config/opencode/AGENTS.md` (OpenCode)
- `~/.gemini/GEMINI.md` (Gemini CLI)
- `~/.config/antigravity/AGENTS.md` (Antigravity)

This ensures all agents follow the same coding standards and NixOS-specific rules regardless of which tool is invoked.

## Applying Changes

The [`rebuild.sh`](rebuild.sh) script is the single entry point for applying system or Home Manager changes:

```bash
./rebuild.sh
```

It does two things:

1. **Stages untracked files** - runs `git add .` because Nix Flakes ignore files not tracked by Git
2. **Rebuilds and switches** - runs `sudo nixos-rebuild switch --flake .#portable`

> **Note:** Changes to files managed via `mkOutOfStoreSymlink` (Neovim, WezTerm, Herdr configs) do **not** require a rebuild. Only changes to `.nix` files need `./rebuild.sh`.

## Portability Notes

- **GRUB with `efiInstallAsRemovable`** - installs the bootloader to the fallback EFI path (`EFI/BOOT/BOOTX64.EFI`), so the USB boots on any UEFI machine without touching the host's NVRAM
- **`canTouchEfiVariables = false`** - prevents writing to the host's EFI variables
- **Redistributable firmware enabled** - ensures Wi-Fi and Bluetooth work on a wide range of hardware
- **Both Intel and AMD KVM/microcode** - the same image works on either CPU vendor
- **`hardwareClockInLocalTime`** - prevents the RTC from drifting when the USB is also used on a Windows machine
- **Battery threshold via udev** - caps charging at 60% using hardware-agnostic udev rules that work across Framework, Asus, ThinkPad, and other vendors
